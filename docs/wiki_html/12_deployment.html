12. Deployment Guide

Docker Compose (Production)

The production.yml file defines all services. Key services:

Service Image Role
django Custom (compose/django/) Gunicorn WSGI server
postgres postgres:14 Database
redis redis:6 Broker + cache
nginx Custom (compose/nginx/) Reverse proxy + SSL
certbot certbot/certbot SSL certificate renewal
celeryworker Same as django Background task worker
celerybeat Same as django Periodic task scheduler
flower Same as django Celery monitoring (optional)

Starting Production

# First deploy
docker-compose -f production.yml up -d --build

# View logs
docker-compose -f production.yml logs -f django

# Run migrations after deploy
docker-compose -f production.yml run --rm django python manage.py migrate

# Collect static files
docker-compose -f production.yml run --rm django python manage.py collectstatic --no-input

Environment Setup (Production)

  1. Copy and populate environment file:
cp env.example .env
  1. Key production values to set:
DJANGO_SETTINGS_MODULE=config.settings.production
DJANGO_SECRET_KEY=<unique-50-char-key>
DJANGO_DEBUG=False
DJANGO_ALLOWED_HOSTS=yourdomain.com,www.yourdomain.com
DATABASE_URL=postgres://user:pass@postgres:5432/mscc_10012023
CELERY_BROKER_URL=redis://redis:6379/0
AZURE_ACCOUNT_NAME=<azure-storage-account>
AZURE_ACCOUNT_KEY=<azure-storage-key>
AZURE_CONTAINER=media
DJANGO_SENTRY_DSN=<sentry-dsn>
DJANGO_SECURE_SSL_REDIRECT=True

SSL Certificates

SSL is handled by Certbot (Let's Encrypt) via the certbot service in production.yml.

Initial certificate issuance:

docker-compose -f production.yml run --rm certbot certonly \
  --webroot -w /var/www/certbot \
  -d yourdomain.com -d www.yourdomain.com \
  --email admin@yourdomain.com --agree-tos --no-eff-email

Certificates auto-renew via the certbot service. Nginx reloads automatically.

Database Backups

Manual Backup

docker-compose -f production.yml exec postgres \
  pg_dump -U postgresuser mscc_10012023 > backup_$(date +%Y%m%d).sql

Restore

docker-compose -f production.yml exec -T postgres \
  psql -U postgresuser mscc_10012023 < backup_20240101.sql

Automated Backups

The compose/postgres/ directory contains backup scripts. Configure a cron job or use Azure Database for PostgreSQL which has automated backup built in.

Deploying Updates

Standard Update Process

# 1. Pull latest code
git pull origin main

# 2. Rebuild Django image
docker-compose -f production.yml build django

# 3. Run migrations (zero-downtime if additive)
docker-compose -f production.yml run --rm django python manage.py migrate

# 4. Collect static files
docker-compose -f production.yml run --rm django python manage.py collectstatic --no-input

# 5. Restart application with zero downtime
docker-compose -f production.yml up -d --no-deps django celeryworker celerybeat

Rolling Back

# Roll back to previous image
git checkout <previous-commit>
docker-compose -f production.yml build django
docker-compose -f production.yml up -d --no-deps django

# Roll back migration (if needed)
docker-compose -f production.yml run --rm django python manage.py migrate myapp <previous-migration>

Process Management

Gunicorn Configuration

Gunicorn is started with the gevent worker class for high concurrency:

# From compose/django/start
gunicorn config.wsgi:application \
  --bind 0.0.0.0:5000 \
  --worker-class gevent \
  --workers 4 \
  --timeout 120 \
  --log-level info

Tune --workers to 2 * CPU_CORES + 1 as a starting point.

Celery Workers

# Worker (started by docker-compose celeryworker service)
celery -A config.celery_app worker \
  -Q default,mscc_export \
  --concurrency 4 \
  -l info

# Beat scheduler
celery -A config.celery_app beat -l info

Monitoring

Application Health

# Check Django is responding
curl -f http://localhost:8000/about/ || echo "Django is down"

# Check Gunicorn workers
docker-compose -f production.yml exec django ps aux | grep gunicorn

# Check Celery
docker-compose -f production.yml exec celeryworker celery -A config.celery_app status

Log Locations

Component Log location
Django / Gunicorn docker-compose logs django
Nginx docker-compose logs nginx
Celery docker-compose logs celeryworker
PostgreSQL docker-compose logs postgres

Sentry

Unhandled exceptions are automatically captured and sent to Sentry (configured via DJANGO_SENTRY_DSN). Check the Sentry dashboard for error rates and stack traces.

Scaling

Horizontal Scaling (multiple Django instances)

  • Run multiple Gunicorn containers behind the Nginx load balancer
  • All instances must share the same Redis and PostgreSQL
  • Session storage is in Redis (supports multiple nodes)
  • Static files served by Nginx (shared volume or Azure CDN)

Celery Worker Scaling

  • Increase --concurrency for the default queue
  • Keep mscc_export queue concurrency at 1 to avoid DB overload during large exports
  • Run additional celeryworker containers as needed

Windows / IIS Deployment

A web.config file is included in the project root for IIS-based deployments (Azure App Service or on-premise IIS). This configures URL rewriting and WSGI handler mapping. Refer to web.config and the Azure App Service docs for specifics.
