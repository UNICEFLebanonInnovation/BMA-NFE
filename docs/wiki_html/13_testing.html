13. Testing Guide

Testing Stack

Tool Purpose
pytest Test runner
pytest-django Django integration for pytest
factory-boy Test data factories (replaces fixtures)
django-test-plus Helpers for testing Django views
coverage / django-coverage-plugin Code coverage measurement
flake8 Linting

Running Tests

# Run all tests
docker-compose -f local.yml run --rm django pytest

# Run tests in a specific app
docker-compose -f local.yml run --rm django pytest student_registration/mscc/

# Run a specific test file
docker-compose -f local.yml run --rm django pytest student_registration/mscc/tests/test_views.py

# Run a specific test
docker-compose -f local.yml run --rm django pytest student_registration/mscc/tests/test_views.py::TestRegistrationListView::test_requires_login

# Run with verbose output
docker-compose -f local.yml run --rm django pytest -v

# Stop on first failure
docker-compose -f local.yml run --rm django pytest -x

Code Coverage

# Run tests with coverage
docker-compose -f local.yml run --rm django coverage run -m pytest

# View coverage report in terminal
docker-compose -f local.yml run --rm django coverage report

# Generate HTML report
docker-compose -f local.yml run --rm django coverage html
# Open htmlcov/index.html in a browser

Coverage configuration is in .coveragerc (or setup.cfg). The django-coverage-plugin ensures template coverage is counted.

Test Settings

Tests use config/settings/test.py (configured in pytest.ini):

# pytest.ini
[pytest]
DJANGO_SETTINGS_MODULE = config.settings.test

Test settings differences from local:
- In-memory SQLite database (faster) or a separate test PostgreSQL database
- Celery tasks always run eagerly
- Password hashing uses MD5 (faster than Argon2 for tests)
- No external API calls (mock any external services)

Writing Tests

Model Tests

# student_registration/mscc/tests/test_models.py
import pytest
from student_registration.mscc.tests.factories import RegistrationFactory

@pytest.mark.django_db
class TestRegistration:
    def test_str(self):
        reg = RegistrationFactory()
        assert str(reg)  # has a __str__ representation

    def test_soft_delete(self):
        reg = RegistrationFactory()
        reg.deleted = True
        reg.save()
        assert not Registration.objects.filter(pk=reg.pk, deleted=False).exists()

View Tests

# student_registration/mscc/tests/test_views.py
import pytest
from django.urls import reverse
from student_registration.users.tests.factories import UserFactory

@pytest.mark.django_db
class TestRegistrationListView:
    def test_requires_login(self, client):
        url = reverse('mscc:list')
        response = client.get(url)
        assert response.status_code == 302  # Redirects to login

    def test_mscc_user_can_access(self, client):
        user = UserFactory(groups=['MSCC'])
        client.force_login(user)
        url = reverse('mscc:list')
        response = client.get(url)
        assert response.status_code == 200

    def test_filters_by_center(self, client):
        user = UserFactory(groups=['MSCC_CENTER'])
        reg_own = RegistrationFactory(center=user.center)
        reg_other = RegistrationFactory()  # different center
        client.force_login(user)
        response = client.get(reverse('mscc:list'))
        assert reg_own in response.context['object_list']
        assert reg_other not in response.context['object_list']

API Tests

# student_registration/mscc/tests/test_api.py
import pytest
from rest_framework.test import APIClient

@pytest.mark.django_db
class TestSchoolAPI:
    def test_list_requires_auth(self):
        client = APIClient()
        response = client.get('/api/schools/')
        assert response.status_code == 401

    def test_authenticated_user_can_list(self):
        user = UserFactory()
        client = APIClient()
        client.force_authenticate(user=user)
        response = client.get('/api/schools/')
        assert response.status_code == 200

Test Factories

Use factory-boy to create test data. Define factories in each app's tests/factories.py:

# student_registration/mscc/tests/factories.py
import factory
from factory.django import DjangoModelFactory
from student_registration.mscc.models import Registration

class RegistrationFactory(DjangoModelFactory):
    class Meta:
        model = Registration

    child = factory.SubFactory('student_registration.child.tests.factories.ChildFactory')
    round = factory.SubFactory('student_registration.mscc.tests.factories.RoundFactory')
    partner = factory.SubFactory('student_registration.schools.tests.factories.PartnerFactory')
    center = factory.SubFactory('student_registration.locations.tests.factories.CenterFactory')
    status = 'active'
    deleted = False

Common Test Patterns

Testing with permissions

from django.contrib.auth.models import Group

def make_user_with_group(group_name):
    user = UserFactory()
    group, _ = Group.objects.get_or_create(name=group_name)
    user.groups.add(group)
    return user

Mocking external APIs

from unittest.mock import patch

@patch('student_registration.mscc.views.call_unique_id_api')
def test_registration_with_mocked_api(mock_api, client):
    mock_api.return_value = {'id': '12345'}
    # ... test body

Testing Celery tasks

In test settings, CELERY_TASK_ALWAYS_EAGER = True makes tasks run synchronously, so you can test the full flow without a worker:

@pytest.mark.django_db
def test_export_task():
    history = ExportHistoryFactory(status='pending')
    generate_mscc_export(export_id=history.pk)  # runs synchronously in tests
    history.refresh_from_db()
    assert history.status == 'done'

Debugging Real Issues

This section covers step-by-step debugging approaches for the most commonly reported production issues.

Missing Attendance Records

When attendance records are not appearing, trace the filtering pipeline using print statements at each step:

print("STEP 1:", registrations.count())
print("STEP 2:", education_services.count())
print("STEP 3:", attendance_records.count())

Check each step in order. If STEP 1 is empty, the registration filter is the problem (wrong center/round). If STEP 2 is empty, the education service filter is the problem (wrong programme/section). If STEP 3 is empty, attendance was never saved.

Date Validation Not Working

Ensure validation exists at BOTH layers:

  • Frontend: JavaScript must block invalid dates before the form submits.
  • Backend: Django Forms clean() method must re-validate — never rely only on frontend validation.

Export Failures

Exports depend on database views. If an export fails or returns no data, check that the relevant view exists and is populated:

SELECT * FROM vw_mscc_attendance_absence;

Common causes: the view definition is stale, a migration dropped/altered an underlying table, or the filter parameters return no rows.

Frontend Conditional Field Logic

Conditional fields are controlled via jQuery. If a conditional field is not showing or hiding correctly, inspect the JS event handler for the controlling field:

if (education_status == 'Dropout') {
    $('#dropout_date').show();
    $('#dropout_date').prop('required', true);
}

Ensure the selector matches the actual rendered field ID, and that the triggering event (change, input) is correct for the field type.
