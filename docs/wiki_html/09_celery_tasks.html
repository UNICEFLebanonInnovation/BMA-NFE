9. Background Tasks (Celery)

Overview

Celery handles operations that are too slow for a synchronous HTTP request — primarily large data export jobs.

Component Technology
Task broker Redis
Result backend Django database (django-celery-results)
Scheduler django-celery-beat
Monitoring Flower (port 5555)

Configuration

Celery is initialized in student_registration/taskapp/celery.py and configured in config/settings/base.py.

Key Settings

# Broker and result backend
CELERY_BROKER_URL = env('CELERY_BROKER_URL', default='redis://localhost:6379/0')
CELERY_RESULT_BACKEND = 'django-db'

# Two queues
CELERY_TASK_QUEUES = {
    Queue('default', routing_key='default'),
    Queue('mscc_export', routing_key='mscc_export'),
}
CELERY_TASK_DEFAULT_QUEUE = 'default'
CELERY_TASK_ROUTES = {
    'student_registration.mscc.tasks.generate_mscc_export': {
        'queue': 'mscc_export'
    }
}

# Export queue is throttled to prevent DB overload
CELERYD_CONCURRENCY_mscc_export = 1

Development Mode

In config/settings/local.py, tasks run synchronously (no worker needed):

CELERY_TASK_ALWAYS_EAGER = True

Task: generate_mscc_export

Location: student_registration/mscc/tasks.py

This is the only significant Celery task in the system. It runs on the mscc_export queue.

What it does

  1. Receives an export_id (an ExportHistory record's PK)
  2. Updates ExportHistory.status = 'processing'
  3. Queries Registration + all related service models based on selected fields
  4. Builds an XLSX or CSV file using openpyxl / tablib
  5. Compresses into a ZIP archive
  6. Uploads the ZIP to Azure Blob Storage
  7. Updates ExportHistory.status = 'done' and saves the file_name
  8. Sends a Firebase Cloud Messaging push notification to the requesting user

Triggering an Export

From the UI: The user clicks "Export" on the MSCC list page, selects fields, and submits. The view:
1. Creates an ExportHistory record with status='pending'
2. Calls generate_mscc_export.delay(export_id=history.pk)
3. Returns the export_id to the browser
4. The browser polls /mscc/export-status/<export_id>/ every few seconds
5. When status='done', the download link appears

# Trigger manually from Django shell
from student_registration.mscc.tasks import generate_mscc_export
generate_mscc_export.delay(export_id=123)

Error Handling

If the task fails, ExportHistory.status is set to 'failed' and the exception is logged to Sentry. The user's browser polling will detect the failed status and display an error message.

Periodic Tasks

django-celery-beat manages scheduled tasks. The schedule is stored in the database and manageable via:
- Django admin: /admin/django_celery_beat/
- Management command: python manage.py setup_periodic_tasks (if defined)

Currently configured periodic tasks are managed via the admin panel.

Running Workers

Docker (recommended)

The celeryworker and celerybeat services are defined in local.yml and production.yml and start automatically with docker-compose up.

Manual

# Worker for both queues
celery -A config.celery_app worker -Q default,mscc_export -l info

# Beat scheduler (runs periodic tasks)
celery -A config.celery_app beat -l info

# Both in one process (development only)
celery -A config.celery_app worker --beat -l info

Monitoring with Flower

Flower provides a web UI for monitoring task execution.

Access at: http://localhost:5555

Features:
- Active, pending, and completed task list
- Worker status and concurrency
- Task retry / revoke
- Queue depth monitoring

Writing a New Task

# student_registration/myapp/tasks.py
from config.celery_app import app

@app.task(bind=True, max_retries=3)
def my_background_task(self, record_id):
    try:
        record = MyModel.objects.get(pk=record_id)
        # ... do work ...
    except MyModel.DoesNotExist:
        # Don't retry if record is missing
        return
    except Exception as exc:
        # Retry with exponential backoff
        raise self.retry(exc=exc, countdown=2 ** self.request.retries)

Then call it:

my_background_task.delay(record_id=42)
# or with apply_async for more control:
my_background_task.apply_async(args=[42], countdown=60)  # run after 60s

Debugging Tasks

# View task results in Django shell
from django_celery_results.models import TaskResult
TaskResult.objects.filter(status='FAILURE').order_by('-date_done')[:10]

# Check export history
from student_registration.backends.models import ExportHistory
ExportHistory.objects.filter(status='failed').order_by('-created')[:10]
